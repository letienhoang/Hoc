# Automated consumer bootstrap v1

`new-consumer.ps1` creates a new independently owned MVC/Razor Admin source tree from the pinned Học baseline `6a8605a63d18d35767f520d57d33193f6d15aa29`. It automates the mechanical parts of the [H4-01 manual procedure](consumer-bootstrap-v1.md); it does not initialize a database, start an application, create a remote repository, or replace the separate [H4-02 module starter](module-starter-v1.md).

Run it from a Học tooling checkout with a local checkout of that exact source commit:

```powershell
pwsh ./scripts/productization/new-consumer.ps1 `
  -SourceRoot C:\work\Hoc-source `
  -SourceSha 6a8605a63d18d35767f520d57d33193f6d15aa29 `
  -OutputRoot C:\work\ContosoAdmin `
  -ApplicationId ContosoAdmin `
  -RootUrl https://localhost:44320
```

The default is a dry-run: it validates the source repository, exact SHA, SDK, application identifier, HTTPS origin, destination boundary, and required source structure, then prints the plan without writing. Add `-Apply` only after review. Apply requires a previously nonexistent destination and stages the extracted tracked Git tree before atomically publishing it. It rejects output below the source tree, an existing worktree, reparse points, collisions, invalid input, and an unsupported source revision. No upstream Git metadata, ignored settings, local artifacts, secrets, certificate files, generated client libraries, or untracked files are copied.

The result has `ContosoAdmin.slnx`, renamed projects/namespaces/assemblies/localization identity, `ContosoAdmin`, `ContosoAdmin_Web`, and `ContosoAdmin_Swagger` OpenIddict identities, and `App:SelfUrl` set from `RootUrl`. Web callbacks retain `/signin-oidc`, `/signout-callback-oidc`, and Swagger retains `/swagger/oauth2-redirect.html`. It changes workspace discovery to the consumer solution through the identity rename while retaining the Development secret-overlay, PostgreSQL `Ssl Mode=VerifyFull`, and fail-closed configuration logic.

DemoRecords' six projects, composition, sample tests, and inherited EF migrations/model snapshot are removed. The consumer owns its later schema and migration history; this tool deliberately does not create or apply a replacement migration. The consumer keeps licensing/provenance inputs, `global.json`, `common.props`, `NuGet.Config`, `.gitignore`, and `.gitattributes`. Package locks that record removed sample projects are regenerated by the consumer's first restore.

Validate a generated tree before handoff:

```powershell
pwsh ./scripts/productization/verify-consumer.ps1 -ConsumerRoot C:\work\ContosoAdmin -ApplicationId ContosoAdmin
pwsh ./scripts/productization/new-admin-module.ps1 -ConsumerRoot C:\work\ContosoAdmin -ApplicationId ContosoAdmin -ModuleName Products -EntityName Product -RouteSegment products
dotnet restore C:\work\ContosoAdmin\ContosoAdmin.slnx -m:1 /nr:false
dotnet build C:\work\ContosoAdmin\ContosoAdmin.slnx -c Release --no-restore -m:1 /nr:false
```

Two inherited projects copy ignored `appsettings.secrets.json`; for a secret-free build-only exercise, create empty `{}` placeholders locally in those project directories, as CI does. Do not use placeholders as Development credentials. Restore ABP client libraries in the consumer only when TestServer/Web rendering needs them. Database connections, EF tooling, DbMigrator, migrations, persistent seeds, browser acceptance, deployed runtime, and production configuration all remain separately authorized work.

Use `pwsh ./scripts/productization/test-new-consumer.ps1` for generator safety and structural self-tests. It uses disposable directories and leaves no generated consumer in this repository.
